=== WebSocket transport

With `camel.cli.transport=websocket`, the application dials out to a developer tool over a WebSocket instead of
exchanging files with the Camel CLI (see the
xref:{cq-camel-components}:others:cli-connector.adoc[CLI Connector] documentation for the protocol and the options).

[source,properties]
----
camel.cli.transport = websocket
camel.cli.websocket.url = ws://127.0.0.1:8000/connect?executionId=run-1
----

The tool gets full control of the application: the transport refuses to start with the `prod` profile
(`camel.main.profile=prod`).

==== WebSocket client

* When the application has the `quarkus-websockets-next` extension, its client is used: Vert.x event loop, TLS
  configuration from the https://quarkus.io/guides/tls-registry-reference[Quarkus TLS registry] (see
  `quarkus.camel.cli.websocket.tls-configuration-name` below), Quarkus WebSockets Next client options.
* Otherwise, the JDK WebSocket client is used. No dependency is added to the application for this.

The client in use is logged at startup (`Camel CLI connector uses the quarkus-websockets-next WebSocket client`) and
reported to the tool. Set `camel.cli.websocket.client=jdk` to always use the JDK client.

The connector accepts actions of up to 16 MB from the tool. If the application sets
`quarkus.websockets-next.client.max-message-size` to a lower value, that value applies to the connector too, and a
warning is logged at startup.

The WebSockets Next client sends and accepts frames of up to 64 KB (the Vert.x default, also accepted by most
WebSocket servers): larger messages are split into several frames, and the tool must split the messages it sends
the same way (most WebSocket libraries do). `quarkus.websockets-next.client.max-frame-size` changes the size in both
directions.

NOTE: When `quarkus-websockets-next` is present, this extension sets the default of
`quarkus.websockets-next.client.max-pending-messages` to `0` (no back-pressure, as before Quarkus 3.40): with
back-pressure, the WebSockets Next client stops reading a connection after receiving many messages split in several
frames. This applies to the other WebSockets Next clients of the application too, unless the property is set.
