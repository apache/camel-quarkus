=== Parser modules

Tika parses only the formats whose parser module is on the classpath.
`camel-tika` brings the HTML and plain text modules. For any other format, add its module to your application, e.g. for PDF:

[source,xml]
----
<dependency>
    <groupId>org.apache.tika</groupId>
    <artifactId>tika-parser-pdf-module</artifactId>
</dependency>
----

The Camel Quarkus BOM manages the version of `tika-parser-pdf-module` only.
For other modules, use the version of `org.apache.tika:tika-core` that `camel-tika` brings.

In native mode, the HTML, plain text and PDF modules are supported.

=== Character encodings in native mode

`tika-parser-text-module`, brought by `camel-tika`, registers Tika's `MojibusterEncodingDetector`.
It matches candidate encodings by name (`windows-1252`, `ISO-8859-*`, `Shift_JIS`, ...) at runtime, while native images bundle only a small subset of the JDK charsets by default.
To keep document parsing working, `camel-quarkus-tika` enables all JDK charsets (`-H:+AddAllCharsets`) for your native build when the detector is present.

This adds a few MB to the native executable.
Because the extension requests the charsets, `quarkus.native.add-all-charsets=false` cannot turn them off, and there is no need to set it to `true` yourself.
